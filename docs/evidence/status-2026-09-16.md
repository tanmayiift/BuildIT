## The one thing stopping a full PR review

**Vercel Hobby's sandbox CPU allowance is spent for this billing cycle.**

| Sandbox quota | Used | Hobby limit |
| --- | ---: | ---: |
| Creations | 434 | 5,000 |
| **Active CPU** | **8h 12m** | **5h** |
| Provisioned memory | 49.0 GB-Hrs | 420 GB-Hrs |
| Data transfer | 5.68 GB | 20 GB |

Only CPU is over. On Pro that overage was billed on demand; Hobby stops, which surfaces as
`sandbox_unavailable` / `capacity_exhausted`. **No review can run to completion until the cycle
resets or the plan changes.**

Most of that 8h12m was spent by the *old* execution design, which paid sandbox setup on every single
review. The segmented design pays it once per job. It should use materially less — but that is a
prediction and it stays one until it can be measured.

## The decision, stated once

| Option | Cost | What you get |
| --- | --- | --- |
| **Wait for the cycle to reset** | £0 | Reviews resume, and we finally measure what a segmented review actually costs in CPU |
| **Return to Pro** | ~$20/mo | Reviews work today; overage is billable rather than blocking |

Nothing else is waiting on either choice. Everything that can be built has been.

## Corrections to earlier claims

Three things previously recorded here were wrong, and stayed wrong long enough to matter:

1. *"The web health endpoint returns 404"* was listed as a verified blocker. The route was
   **untracked** — it 404'd because 191 finished files had never been committed.
2. *"Grafana exposes no pause action for provisioned rules."* It does. The update was being sent
   with `x-disable-provenance`, which belongs on create and asks Grafana to rewrite provenance on
   update. Removing it paused 12 of 12.
3. *"Hobby's constraint is a 45-minute sandbox session cap."* It is not. It is 5 CPU-hours a month;
   session length never came into it.

## Still open, and honestly so

- **Model provider credit.** A key exists and reviews get past the credential check. OpenAI's key
  returns 429 `insufficient_quota` — BuildIT now says *"the account has no credit left, this is not
  a rate limit and will not clear on its own"* instead of telling you to wait.
- **AWS credentials in CI.** `smoke:aws-boundary` warns rather than failing, and
  `docs/operations/ci-gates.md` records exactly what goes unverified until the secrets exist.
- **Tracker OAuth and an email sending domain.** Code written and tested; no account to connect to.
- **`findingResolution: "fixed"`** — deliberately unwritten. Marking findings fixed on delivery would
  over-claim; see `docs/operations/known-defects.md`.
